Erzeuge in diesem Repo ein neues, eigenständig startbares .NET 8 Web-API Projekt für VS Code:

- Lege (falls noch nicht vorhanden) eine Solution "BusinessService.sln" an.
- Lege ein startbares ASP.NET Core Web API Projekt "BusinessService.Api" an.
- Das Projekt soll sich in VS Code mit `dotnet build` und `dotnet run` starten lassen (Kestrel, HTTP-API auf einem konfigurierbaren Port, z.B. 5000).

Der BusinessService kapselt die fachliche Domäne "Validation".
Er verwaltet:
- Users (mit eindeutiger E-Mail-Adresse) und
- Validations von Frage-Antwort-Paaren inkl. ValidationSteps.

Ein separater Dienst "AiService" übernimmt ausschließlich KI-Bewertungen über eine REST-API, für die es im BusinessService einen mit NSwag generierten Client geben wird.

=====================================
1. DOMAINMODELL
=====================================

Implementiere in einem geeigneten Namespace (z.B. BusinessService.Domain) folgende Entities:

public class User
{
    public Guid Id { get; set; }
    public string Email { get; set; } = default!;      // eindeutig, Pflicht
    public string DisplayName { get; set; } = default!;

    public ICollection<Validation> Validations { get; set; } = new List<Validation>();
}

public class Validation
{
    public Guid Id { get; set; }

    public Guid UserId { get; set; }
    public User User { get; set; } = default!;

    public string Question { get; set; } = default!;
    public string InitialAnswer { get; set; } = default!;
    public DateTime CreatedAt { get; set; }
    public bool IsCompleted { get; set; }

    public ICollection<ValidationStep> Steps { get; set; } = new List<ValidationStep>();
}

public class ValidationStep
{
    public Guid Id { get; set; }

    public Guid ValidationId { get; set; }
    public Validation Validation { get; set; } = default!;

    public DateTime CreatedAt { get; set; }

    // Frage des Systems an den Nutzer
    public string Inquiry { get; set; } = default!;

    // Antwort des Nutzers auf diese Inquiry
    public string UserAnswer { get; set; } = default!;

    // Bewertung der Antwort in einem einheitlichen Bereich (z.B. 0..1)
    public double? Score { get; set; }

    // Optionale Erläuterung der KI
    public string? AiExplanation { get; set; }

    // Markiert, ob dieser Step die Validation fachlich abschließt
    public bool IsFinal { get; set; }
}

=====================================
2. DATENBANK / EF CORE
=====================================

Lege einen DbContext "BusinessDbContext" an, z.B. im Namespace BusinessService.Infrastructure:

public class BusinessDbContext : DbContext
{
    public DbSet<User> Users => Set<User>();
    public DbSet<Validation> Validations => Set<Validation>();
    public DbSet<ValidationStep> ValidationSteps => Set<ValidationStep>();

    public BusinessDbContext(DbContextOptions<BusinessDbContext> options) : base(options) { }

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        // User: E-Mail eindeutig
        modelBuilder.Entity<User>()
            .HasIndex(u => u.Email)
            .IsUnique();

        modelBuilder.Entity<User>()
            .HasMany(u => u.Validations)
            .WithOne(v => v.User)
            .HasForeignKey(v => v.UserId);

        modelBuilder.Entity<Validation>()
            .HasMany(v => v.Steps)
            .WithOne(s => s.Validation)
            .HasForeignKey(s => s.ValidationId);
    }
}

- Verwende SQLite (z.B. Connection-String: "Data Source=business.db;").
- Richte Migrations ein (Code First).
- Verwende DateTime.UtcNow für alle CreatedAt-Felder.

=====================================
3. ARCHITEKTUR: CONTROLLER & MANAGER
=====================================

Die HTTP-API-Endpunkte sollen NICHT direkt in Program.cs (keine Minimal APIs) stehen, sondern in einem Controller gekapselt sein.

- Lege einen Controller "BusinessServiceController" im Namespace BusinessService.Api.Controllers an.
- Dieser Controller kapselt alle Business-Endpoints:

  - POST /api/users/get-or-create
  - POST /api/validations
  - GET  /api/validations?userId=...
  - GET  /api/validations/{validationId}
  - POST /api/validations/{validationId}/validate

- Die Controller-Methoden enthalten KEINE Business-Logik.
- Erstelle eine Service-/Manager-Klasse "ValidationManager" (z.B. im Namespace BusinessService.Application oder BusinessService.Domain.Services).
- ValidationManager kapselt die gesamte Logik rund um Users, Validations und ValidationSteps.

Beispielhafte Signaturen im ValidationManager (du kannst Namen anpassen, Funktionalität muss entsprechen):

public class ValidationManager
{
    private readonly BusinessDbContext _dbContext;
    // optional: AiService-Client über DI

    public ValidationManager(BusinessDbContext dbContext /*, AiServiceClient aiClient */)
    {
        _dbContext = dbContext;
    }

    public Task<UserDto> GetOrCreateUserAsync(GetOrCreateUserRequest request, CancellationToken cancellationToken);
    public Task<ValidationDto> CreateValidationAsync(CreateValidationRequest request, CancellationToken cancellationToken);
    public Task<List<ValidationListItemDto>> GetValidationsForUserAsync(Guid userId, CancellationToken cancellationToken);
    public Task<ValidationDetailsDto?> GetValidationByIdAsync(Guid validationId, CancellationToken cancellationToken);
    public Task<ValidateStepResponse?> ValidateStepAsync(Guid validationId, ValidateStepRequest request, CancellationToken cancellationToken);
}

- Der BusinessServiceController ruft nur diese Methoden auf.

=====================================
4. HTTP-API (RICHTUNG UI)
=====================================

Implementiere im BusinessServiceController folgende Endpunkte und DTOs.

-------------------------------------
4.1 POST /api/users/get-or-create
-------------------------------------

Zweck:
- Benutzer anhand seiner E-Mail identifizieren oder neu anlegen.
- E-Mail ist Pflicht und eindeutig.

Request-DTO:

public class GetOrCreateUserRequest
{
    public string Email { get; set; } = default!;
    public string DisplayName { get; set; } = default!;
}

Response-DTO:

public class UserDto
{
    public Guid Id { get; set; }
    public string Email { get; set; } = default!;
    public string DisplayName { get; set; } = default!;
}

Ablauf:

1. ValidationManager.GetOrCreateUserAsync aufrufen.
2. Dieser:
   - sucht in der DB nach User.Email,
   - legt ggf. einen neuen User an,
   - gibt UserDto zurück.

-------------------------------------
4.2 POST /api/validations
-------------------------------------

Zweck:
- Neue Validation für einen bestehenden User anlegen.

Request-DTO:

public class CreateValidationRequest
{
    public Guid UserId { get; set; }
    public string Question { get; set; } = default!;
    public string InitialAnswer { get; set; } = default!;
}

Response-DTO:

public class ValidationDto
{
    public Guid Id { get; set; }
    public Guid UserId { get; set; }
    public string Question { get; set; } = default!;
    public string InitialAnswer { get; set; } = default!;
    public bool IsCompleted { get; set; }
}

Ablauf (im ValidationManager):

1. Prüfen, ob User mit UserId existiert; falls nicht, Fehler (Controller → 404).
2. Neue Validation mit:
   - Id = Guid.NewGuid()
   - UserId = aus Request
   - Question, InitialAnswer
   - CreatedAt = DateTime.UtcNow
   - IsCompleted = false
3. Speichern und als ValidationDto zurückgeben.

-------------------------------------
4.3 GET /api/validations?userId={userId}
-------------------------------------

Zweck:
- Alle Validations eines Users zurückgeben.

Response-DTO (Liste von):

public class ValidationListItemDto
{
    public Guid Id { get; set; }
    public string Question { get; set; } = default!;
    public bool IsCompleted { get; set; }
    public DateTime CreatedAt { get; set; }
}

Ablauf (im ValidationManager):

1. userId prüfen, optional User-Existenz prüfen.
2. Alle Validations mit diesem UserId laden.
3. Auf ValidationListItemDto mappen.
4. Liste zurückgeben.

-------------------------------------
4.4 GET /api/validations/{validationId}
-------------------------------------

Zweck:
- Eine einzelne Validation inkl. Steps zurückgeben.

Response-DTO:

public class ValidationDetailsDto
{
    public Guid Id { get; set; }
    public Guid UserId { get; set; }
    public string Question { get; set; } = default!;
    public string InitialAnswer { get; set; } = default!;
    public bool IsCompleted { get; set; }
    public DateTime CreatedAt { get; set; }
    public List<ValidationStepDto> Steps { get; set; } = new();
}

public class ValidationStepDto
{
    public Guid Id { get; set; }
    public DateTime CreatedAt { get; set; }
    public string Inquiry { get; set; } = default!;
    public string UserAnswer { get; set; } = default!;
    public double? Score { get; set; }
    public string? AiExplanation { get; set; }
    public bool IsFinal { get; set; }
}

Ablauf (im ValidationManager):

1. Validation inkl. Steps laden.
2. Falls nicht gefunden: null → Controller gibt 404.
3. Auf ValidationDetailsDto mappen (Steps z.B. nach CreatedAt sortiert).

-------------------------------------
4.5 POST /api/validations/{validationId}/validate
-------------------------------------

Zweck:
- Eine Nutzerantwort auf eine bestehende Inquiry verarbeiten,
- sie vom AiService bewerten lassen
- und ggf. eine neue Inquiry zurückgeben.

Request-DTO:

public class ValidateStepRequest
{
    public string Inquiry { get; set; } = default!;
    public string UserAnswer { get; set; } = default!;
}

Response-DTO:

public class ValidateStepResponse
{
    public Guid ValidationId { get; set; }
    public bool IsCompleted { get; set; }
    public double Score { get; set; }
    public string AiExplanation { get; set; } = default!;
    public string? NextInquiry { get; set; }
}

Ablauf (im ValidationManager):

1. Validation inkl. Steps laden; wenn nicht vorhanden → null (Controller: 404).
2. Neuen ValidationStep mit:
   - Id = Guid.NewGuid()
   - ValidationId = validationId
   - CreatedAt = DateTime.UtcNow
   - Inquiry, UserAnswer aus Request
   - Score = null, AiExplanation = null, IsFinal = false
   anlegen (und dem Context hinzufügen).
3. Ein AiScoreStepRequest für den AiService bauen (siehe Abschnitt 5).
4. AiService-Client aufrufen und AiScoreStepResponse erhalten.
5. Step mit Score, AiExplanation, IsFinal aktualisieren.
6. Falls IsFinal = true:
   - Validation.IsCompleted = true.
7. Änderungen speichern.
8. ValidateStepResponse zurückgeben.

=====================================
5. ANBINDUNG AN DEN AISERVICE
=====================================

Der AiService ist ein separater Microservice mit einem Endpoint POST /api/ai/score-step.
Im BusinessService wird aus dessen OpenAPI-Spezifikation ein C#-Client mit NSwag generiert (z.B. AiServiceClient).

Die DTOs für den Call sollen so aussehen:

public class AiScoreStepRequest
{
    public Guid ValidationId { get; set; }
    public string Question { get; set; } = default!;
    public string InitialAnswer { get; set; } = default!;
    public string Inquiry { get; set; } = default!;
    public string UserAnswer { get; set; } = default!;
}

public class AiScoreStepResponse
{
    public double Score { get; set; }
    public string AiExplanation { get; set; } = default!;
    public bool IsFinal { get; set; }
    public string? NextInquiry { get; set; }
}

Im ValidationManager in ValidateStepAsync:

- Aus Validation und dem neuen Step ein AiScoreStepRequest bauen:

var aiRequest = new AiScoreStepRequest
{
    ValidationId = validation.Id,
    Question = validation.Question,
    InitialAnswer = validation.InitialAnswer,
    Inquiry = step.Inquiry,
    UserAnswer = step.UserAnswer
};

- Über den (später generierten) AiService-Client den Endpoint POST /api/ai/score-step aufrufen.
- Ergebnis in AiScoreStepResponse entgegennehmen.
- Score, AiExplanation, IsFinal in den Step übernehmen.
- Falls IsFinal = true, Validation.IsCompleted = true setzen.
- NextInquiry im ValidateStepResponse an die UI zurückgeben.

=====================================
6. PROGRAM.CS / STARTUP
=====================================

Program.cs im Projekt BusinessService.Api soll:

- WebApplicationBuilder und WebApplication erstellen.
- den BusinessDbContext mit SQLite registrieren (Connection-String z.B. aus appsettings.json).
- den ValidationManager als Service registrieren.
- den AiService-Client registrieren (als Platzhalter kannst du hier ein Interface bzw. eine Dummy-Implementierung vorsehen, bis NSwag-Client vorhanden ist).
- Controller-Support aktivieren und den BusinessServiceController einbinden.
- den Webserver starten und die API unter /api/... verfügbar machen.

Allgemeine Anforderungen:

- DateTime.UtcNow für Zeitstempel.
- Sinnvolle Fehlerbehandlung (404 bei nicht existierenden Resources, 400 bei invaliden Requests).
- Code kompilierbar, saubere Namespaces, keine Business-Logik in Program.cs oder im Controller – alles in den Manager ausgelagert.
