- Lege das Projekt im Ordner "ValidationScoringService.Api" an, auf derselben Ebene wie "BusinessService.Api".
- Verwende "ValidationScoringService.Api" als Projektnamen und Root-Namespace.

Architekturvorgaben:

- Die Struktur soll sich so nah wie möglich an der des BusinessService orientieren.
- Verwende analoge Namespaces und Ordner:
  - ValidationScoringService.Api.Controllers
  - ValidationScoringService.Api.Contracts

- Program.cs soll wie beim BusinessService aufgebaut sein: Host erstellen, Services registrieren, Controller aktivieren, API starten.

Controller:

Lege einen Controller an, der sich strukturell am BusinessServiceController orientiert:

- Namespace: ValidationScoringService.Api.Controllers
- Klassenname: ValidationScoringController
- Attribute:
  - [ApiController]
  - [ApiConventionType(typeof(PxDefaultApiConventions))]
  - [Produces(MediaTypeNames.Application.Json)]
  - [Route("api/ai")]
  - [SystemTextJsonFormatter]
  - [ApiExplorerSettings(GroupName = "Nswag")]

Der Controller soll nur EINEN fachlichen Endpoint haben:

- POST /api/ai/score-step
- Signatur:

  [HttpPost("score-step")]
  public Task<ActionResult<AiScoreStepResponse>> ScoreStepAsync(
      [FromBody] AiScoreStepRequest request,
      CancellationToken cancellationToken)

- Der Controller soll KEINE Business-Logik enthalten.
- Nutze ein privates ExecuteAsync<T>-Hilfsmethode analog zum BusinessServiceController, um Fehler auf 400/404 abzubilden. Die Methode soll:
  - ArgumentException und InvalidOperationException in BadRequest (400) mappen,
  - KeyNotFoundException in NotFound (404) mappen,
  - ansonsten 200 (OK) mit dem Ergebnis zurückgeben.

Manager:

Lege einen Manager analog zum BusinessServiceManager an:

- Namespace: ValidationScoringService.Api.Managers
- Interface:

  public interface IValidationScoringManager
  {
      Task<AiScoreStepResponse> ScoreStepAsync(
          AiScoreStepRequest request,
          CancellationToken cancellationToken);
  }

- Implementierung:

  public sealed class ValidationScoringManager : IValidationScoringManager
  {
      private readonly ILLMClient llmClient;

      public ValidationScoringManager(ILLMClient llmClient)
      {
          this.llmClient = llmClient ?? throw new ArgumentNullException(nameof(llmClient));
      }

      public async Task<AiScoreStepResponse> ScoreStepAsync(
          AiScoreStepRequest request,
          CancellationToken cancellationToken)
      {
          // einfache Input-Validierung:
          // wir erwarten, dass Question, InitialAnswer, Inquiry und UserAnswer nicht null/leer/Whitespace sind
          if (request.ValidationId == Guid.Empty)
              throw new ArgumentException("ValidationId must not be empty.", nameof(request));
          if (string.IsNullOrWhiteSpace(request.Question))
              throw new ArgumentException("Question must not be empty.", nameof(request));
          if (string.IsNullOrWhiteSpace(request.InitialAnswer))
              throw new ArgumentException("InitialAnswer must not be empty.", nameof(request));
          if (string.IsNullOrWhiteSpace(request.Inquiry))
              throw new ArgumentException("Inquiry must not be empty.", nameof(request));
          if (string.IsNullOrWhiteSpace(request.UserAnswer))
              throw new ArgumentException("UserAnswer must not be empty.", nameof(request));

          // Aufruf des LLM-Clients
          var modelResult = await llmClient.EvaluateStepAsync(request, cancellationToken)
              .ConfigureAwait(false);

          // Mapping auf Response-DTO
          return new AiScoreStepResponse
          {
              Score = modelResult.Score,
              AiExplanation = modelResult.Explanation,
              IsFinal = modelResult.IsFinal,
              NextInquiry = modelResult.NextInquiry
          };
      }
  }

Program.cs / DI:

- Program.cs soll analog zum BusinessService aufgebaut sein (gleiche Stilistik, gleicher Hosting-Ansatz).
- Registriere die Services:

  builder.Services.AddControllers();
  // evtl. gleiche JSON-Options wie im BusinessService

  builder.Services.AddScoped<IValidationScoringManager, ValidationScoringManager>();
  builder.Services.AddScoped<ILLMClient, LLMClientMock>();

- Kein DbContext, keine Datenbank, keine Persistenz:
  - Der komplette Kontext (ValidationId, Question, InitialAnswer, Inquiry, UserAnswer) wird immer vollständig im AiScoreStepRequest vom BusinessService übergeben.
  - Der ValidationScoringService ist zustandslos, speichert nichts dauerhaft und hat keinen eigenen Session-Store.

Sonstiges:

- Erzeuge keine zusätzlichen fachlichen Endpoints, keine eigene Datenbank und keine alternative DTOs – nutze exakt die hier definierten Typen und Signaturen.
